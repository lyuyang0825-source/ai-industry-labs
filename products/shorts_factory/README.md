# shorts-factory · 从一句选题到可执行的分镜包

把“选题 → 钩子 → 分镜 → 口播稿 → SRT → 多平台改版 → 合规检查”串成一条离线可跑的流水线，最后能直接渲出一条带时间轴的样片用于内部过片。

> 样片是**分镜渲染**（字幕 + 镜头卡），不是终版成片；它的作用是让剪辑、拍摄、运营在同一个时间轴上对齐，再替换成实拍或生成素材。

## 为什么做这个方向

- 短视频生产的瓶颈已经不是“能不能生成画面”，而是**有效成片率**：2026 年一季度上线的 AI 微短剧中，播放量破亿的头部作品占比仅 0.117%，大量内容是“无效产出”。
- 单条成本并不低：精品 AI 漫剧每分钟制作成本约 4000 元，普通质量也要 1500 元/分钟；反复抽卡、人工修复会继续叠加时间与人力。
- 真正的浪费发生在前期：脚本没有钩子、镜头没有信息增量、同一内容要手工改 3 个平台版本、发布前没人查绝对化用语。
- 这个工具不解决“生成得多像”，只解决**“这一条值不值得做、每一秒拍什么、每个平台怎么改”**。

## 产品定义

| 模块 | 输入 | 输出 |
| --- | --- | --- |
| 钩子 | 选题 + 受众 | 3 条可 A/B 的 3 秒钩子 |
| 叙事 | 3 个要点 | 6 段结构（钩子/痛点/标准/行动/边界/CTA） |
| 分镜 | 目标时长 | 逐镜表：时间、景别、画面、口播、转场、B-roll 位 |
| 字幕 | 分镜口播 | SRT + 纯文本口播稿（带时间戳） |
| 多平台 | 平台清单 | 9:16 / 3:4 / 16:9 的标题、封面、话题、时长与改版建议 |
| 合规 | 全量文案 | 绝对化用语、医疗/金融承诺、封面超长、时长超限 |
| 渲染 | 分镜 | 带字幕与进度条的 MP4 样片 + 封面 PNG |

### 时间轴怎么算

1. 按中文口播 4.5 字/秒估算每句自然时长（下限 1.6 秒，避免闪帧）；
2. 总时长不足目标时，把余量按段落权重分配成 **B-roll 素材位**（≥3 秒才建位）；
3. 总时长超出目标时，整体等比压缩，并给出“需删减多少字 / 建议时长放到多少秒”的提示，而不是偷偷加速；
4. 最后把浮点误差吸收到最后一镜，保证总时长严格等于目标。

## 快速开始

```bash
cd products/shorts_factory
python3 -m shorts_factory.cli --brief samples/brief_zh_01.json --out-dir demo_out --render
```

无需第三方 Python 依赖；`--render` 需要系统安装 `ffmpeg`，中文字体使用 Noto Sans CJK（Linux 常见路径，找不到会回退）。

输出：

```
demo_out/
├── storyboard.md     # 分镜包：钩子候选、分镜表、多平台版本、合规、拍摄清单
├── plan.json         # 结构化分镜（含每镜起止时间）
├── subtitles.srt     # 可直接导入剪映/PR
├── voiceover.txt     # 口播稿（带时间戳）
├── platforms.json    # 各平台标题/封面/话题/ffmpeg 命令
├── compliance.md     # 发布前检查
├── cover.png         # 3:4 封面
└── demo_9x16.mp4     # 60 秒样片（720×1280，字幕烧录）
```

## 多平台不是“缩放一下”

- 抖音 / 视频号 / 快手：9:16，前 3 秒必须给钩子，标题分别限 30 / 20 / 25 字；
- 小红书：3:4，封面文字比口播更重要，建议首图直接给结论；
- B 站：16:9，可容纳更长解释，钩子窗口放到 5 秒，但要补原理图或数据来源。

每个平台都会单独给出标题、封面文字、话题、改版说明和 ffmpeg 命令，避免运营手工改 5 遍。

## 合规检查（会阻断发布）

| 规则 | 内容 |
| --- | --- |
| C001 | 绝对化用语：最好、第一、唯一、100%、永久、根治、彻底… |
| C002 | 医疗承诺：治愈、包治、替代就医、保证有效… |
| C003 | 金融承诺：稳赚、保本、无风险、翻倍… |
| C004 | 健康类内容缺少免责声明 |
| C005 | 封面文字超过 12 字，手机端被截断 |
| C006 | 时长超过平台上限，给出删减顺序 |
| C007 | 话题不足 3 个 |

命中 C001–C003 时 CLI 返回码为 2，可直接卡在 CI / 发布脚本里。

## 设计约束（有意为之）

- **不假装懂内容**：模板引擎只负责结构与节奏，案例、数据、观点必须由人补；`plan.json` 里每个 B-roll 位都标了“待补什么”。
- **先时间轴，后画面**：画面可以换，时间轴错了整条重做。
- **字幕以像素宽度折行**，不是简单按字数，避免长句溢出。
- **合规词表可配置**，不同行业可替换 `compliance.py` 的词表。

## 当前限制

- 模板生成的文案偏“骨架”，需要编导补案例或接 LLM 精修；接 LLM 时只替换文案层，时间轴与合规仍由本工具计算。
- 未接 TTS 与图生视频；样片无人声、无真实画面。
- 口播语速按 4.5 字/秒估算，方言、快节奏口播需要按账号历史数据校准。
- 平台规则会变，标题字数与时长上限以发布时后台为准。

## 路线图

- [ ] LLM 适配层：给每个镜头生成 3 个候选口播，人工选一个回填
- [ ] TTS 对齐：按真实语音时长回写时间轴
- [ ] 素材库：B-roll 位自动匹配历史素材并去重
- [ ] 数据回流：把完播率、3 秒留存写回分镜，形成账号自己的钩子模板
- [ ] 团队协作：编导/拍摄/剪辑在同一份 `plan.json` 上批注
