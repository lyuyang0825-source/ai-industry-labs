# support-copilot · 可溯源、会认怂、会交接的客服副驾驶

在回答前先检索知识库，回答时逐条给出引用，拿不准就转人工，转人工时把已收集信息打包好——不做“会说话的墙”。

## 为什么做这个方向

- 成本已经不是问题，信任才是：AI 客服年费几万元就能顶几十个真人坐席，但 2025 年上海市消保委受理的 AI 客服相关投诉达 1087 件，集中在答非所问、人工接入难、流程死循环；黑猫投诉里“转人工”相关投诉超过 3 万条。
- “降本”经常变成“降责”：有在线教育公司上线 AI 客服后，日均对话从 2000 涨到 8000，但满意度下降 15%，转人工率从 20% 飙到 45%，客诉量反而增加 30%。
- 知识库本身是糊涂账：产品手册、退换货政策、促销规则散落在不同文档，业务规则变了也不更新；Gartner 调研显示约 60% 的企业客服机器人实际能解决的问题不到一半，生成式 AI 对复杂售后场景的理解准确率不足 60%。
- 监管已经给出方向：2026 年 9 月 1 日实施的《顾客联络服务 人工与智能客户服务协同要求》明确，智能客服处理标准化问题，复杂/涉安全问题交人工；切换要“便捷入口 + 信息同步、不重复询问”；涉及价格、折扣、退款、赔偿、合同变更，AI 可以解释规则、收集材料、生成工单，但最终确认应由人工完成。

这个产品就是按这条标准做的开源参考实现。

## 产品定义

| 能力 | 实现 |
| --- | --- |
| 知识治理 | Markdown + 元信息（id / 适用口径 / 生效区间 / owner / 风险级别），启动时校验、检测同题冲突 |
| 检索 | 纯标准库 BM25，中文二元组 + 电商同义词扩展 |
| 回答 | 只引用命中的知识原文，回复必带 `依据：kb-xxx` |
| 置信度闸门 | 高分直接答；中分“答 + 需人工确认”；低分拒答并转人工 |
| 越权保护 | 退款金额、赔偿、价格、合同、账号安全等诉求强制人工确认；承诺词扫描 |
| 数字溯源 | 回复里的“3 个工作日”“7 天”等必须能在引用原文找到，否则降级人工 |
| 交接 | 工单包含意图、置信度、已核对知识、已收集字段、缺失字段、交接摘要、`do_not_reask` |
| 质检 | 对已有会话打分：引用覆盖率、越权承诺、该转未转、重复询问 |

### 决策矩阵

| 条件 | 动作 | 说明 |
| --- | --- | --- |
| 置信度 ≥ 0.70 且非高风险意图 | `answer` | 直接答，带引用 |
| 置信度 0.52–0.70 | `answer_with_human` | 给规则解释，同时建工单 |
| 置信度 < 0.52 或意图为 other 且分数 < 8 | `refuse_and_escalate` | 不猜，直接转人工 |
| 退款/赔偿/价格/合同/账号/客诉/法务 | `answer_with_human` | 机器人只解释规则与收集材料，最终人工确认 |
| 问候语 / 过短输入 | `clarify` | 引导补充订单号与问题描述 |

## 知识库格式

```markdown
---
id: kb-refund-001
question: 实物商品支持几天无理由退货
answer: 自签收之日起 7 天内，商品保持完好、配件齐全可申请无理由退货。定制类、生鲜、已拆封的个人护理与贴身用品除外；退款在仓库验收后 3–5 个工作日原路退回。
scope: 实物商品（不含定制、生鲜、已拆封个护）
effective_from: 2025-01-01
effective_to: 2026-12-31
owner: 售后组
risk: high
tags: 退货,退款,售后
---
```

规则：

- 没有 `id` 的知识不允许进入回答；
- `answer` 必须是可独立引用的最小事实，不写“详见页面”；
- 高风险知识必须写明例外/边界，否则 `--lint` 会提示；
- 同题、生效区间重叠但答案不一致 → 判为冲突，必须先治理再上线。

## 快速开始

```bash
cd products/support_copilot

# 单条咨询
python3 -m support_copilot.cli --query "退款多久到账？"

# 带订单上下文（会进入工单，避免人工重复询问）
python3 -m support_copilot.cli \
  --query "我要退款，订单号 A20261124001" \
  --context '{"order_id":"A20261124001"}'

# 跑内置演示集
python3 -m support_copilot.cli --demo

# 知识库体检（冲突 / 缺失 / 高风险边界）
python3 -m support_copilot.cli --lint

# 会话质检
python3 -m support_copilot.cli --eval data/tickets/ticket_02_bad.json
```

### 演示结果

| 咨询 | 动作 | 置信度 | 结果 |
| --- | --- | --- | --- |
| 退款多久到账？ | answer | 0.80 | 引用 kb-refund-001，给出 7 天规则与 3–5 个工作日到账 |
| 我要退款，订单号 A20261124001 | answer_with_human | 0.80 | 解释规则 + 建工单，`do_not_reask=[order_id]` |
| 价保几天？帮我补差价 | answer_with_human | 0.84 | 补差规则 + 人工核价 |
| 账号被冻结了怎么解封 | answer_with_human | 0.83 | 转账户安全组，缺失 `account_id` |
| 发票抬头能改吗 | answer | 0.84 | 30 天内可改一次 |
| 你们支持火星配送吗 | refuse_and_escalate | 0.31 | 不猜，直接转人工 |

质检示例：规范会话 100 分；问题会话 10 分，命中“无引用、越权承诺、该转未转、重复询问订单号、无下一步”。

## 设计约束（有意为之）

- **宁可拒答**：知识没命中就转人工，不用“通用话术”填空。
- **不承诺结果**：退款到账时间、赔偿金额只解释规则，不替业务下结论。
- **引用必须可点开**：每条回答都能回到知识条目与生效区间。
- **工单不是甩锅**：交接摘要写清已查过什么、缺什么，人工不需要用户复述。
- **离线可跑**：无向量库、无外部 API，方便在私有环境做基线；替换为向量检索时，引用与策略层不需要改。

## 当前限制

- BM25 对同义改写仍有限，复杂口语化提问需要向量召回或 LLM 改写 query。
- 知识冲突检测基于“问题文本相同 + 答案不同”，近义问题仍需人工合并。
- 工单只生成结构化 JSON，未对接真实工单系统；生产需接 CRM/客服工作台。
- 质检是规则打分，不等价于真实满意度；需要与 CSAT、一次解决率做校准。

## 路线图

- [ ] 混合检索：BM25 + 向量 + 重排，保留引用约束
- [ ] 多轮槽位填充：订单号、商品、问题类型跨轮继承
- [ ] 工单系统适配器：Zendesk / 飞书服务台 / 自建 CRM
- [ ] 知识发布流水线：业务变更 → 草稿 → 冲突检测 → 生效
- [ ] 质检看板：按意图、坐席、知识条目聚合失败案例
- [ ] 红队测试集：越权承诺、诱导退款、隐私套取
